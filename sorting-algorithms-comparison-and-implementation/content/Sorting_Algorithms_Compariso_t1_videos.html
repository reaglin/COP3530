Introduction

Sorting is one of the most studied problems in computer science: given a collection of items and a rule for comparing them, rearrange the collection so the items appear in order. It sounds simple, but the way you do it determines how much time and memory your program consumes, and that difference becomes dramatic as data grows from dozens of elements to millions.

In this module you will implement several sorting algorithms, so this introductory topic gives you the vocabulary and measuring tools you need first. Key terms include comparison-based sorting, stability (whether equal elements keep their original relative order), in-place sorting (whether extra memory proportional to the input is required), and best, average, and worst cases. Time complexity and space complexity, expressed in Big O notation, are the two formal criteria we use to compare algorithms, while practical performance characteristics explain why an O(n^2) algorithm can still beat an O(n log n) one on small or nearly sorted inputs.

As you watch the videos below, focus on the criteria rather than memorizing any single algorithm. Ask yourself: what is being counted (comparisons, swaps, extra arrays)? How does the cost change when the input is already sorted, reverse sorted, or random? Keep a running glossary of the terms you hear so that when we start coding bubble, insertion, merge, and quicksort in JavaScript, the analysis language is already familiar.
