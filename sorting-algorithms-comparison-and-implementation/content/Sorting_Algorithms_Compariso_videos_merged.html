Introduction to Sorting Algorithms

Introduction

Sorting is one of the most studied problems in computer science: given a collection of items and a rule for comparing them, rearrange the collection so the items appear in order. It sounds simple, but the way you do it determines how much time and memory your program consumes, and that difference becomes dramatic as data grows from dozens of elements to millions.

In this module you will implement several sorting algorithms, so this introductory topic gives you the vocabulary and measuring tools you need first. Key terms include comparison-based sorting, stability (whether equal elements keep their original relative order), in-place sorting (whether extra memory proportional to the input is required), and best, average, and worst cases. Time complexity and space complexity, expressed in Big O notation, are the two formal criteria we use to compare algorithms, while practical performance characteristics explain why an O(n^2) algorithm can still beat an O(n log n) one on small or nearly sorted inputs.

As you watch the videos below, focus on the criteria rather than memorizing any single algorithm. Ask yourself: what is being counted (comparisons, swaps, extra arrays)? How does the cost change when the input is already sorted, reverse sorted, or random? Keep a running glossary of the terms you hear so that when we start coding bubble, insertion, merge, and quicksort in JavaScript, the analysis language is already familiar.

Bubble Sort

Introduction

Bubble sort is the traditional starting point for studying sorting algorithms. The idea is simple: repeatedly walk through the list, compare each pair of adjacent elements, and swap them when they are out of order. Larger values "bubble" toward the end of the array with each pass, and after enough passes the data is sorted. Because the logic is short and visual, bubble sort is an ideal place to build the habits you will need for harder algorithms: tracing nested loops, counting comparisons and swaps, and reasoning about what is guaranteed after each pass.

In this course, bubble sort serves as the baseline against which insertion sort, merge sort, and quicksort are measured. Its nested-loop structure gives O(n^2) comparisons in the average and worst cases, and an early-exit optimization (stop when a full pass produces no swaps) brings the best case down to O(n) on already-sorted input. It sorts in place with O(1) extra space and, when implemented with a strict greater-than comparison, it is stable — properties you will reuse when you compare algorithms later in the module.

The videos below use C++ and Java for their code walkthroughs, so as you watch, focus on the structure rather than the syntax: where the outer loop ends, why the inner loop shrinks on each pass, and where the swap happens. Then rewrite the same logic in JavaScript using a temporary variable or array destructuring for the swap. Pay particular attention to the "swapped" flag in the optimized version and to the honest discussion of when bubble sort is a reasonable choice (tiny or nearly sorted datasets, teaching, quick prototypes) and when it clearly is not (anything large).

Insertion Sort

Introduction

Insertion sort builds a sorted region at the front of an array one element at a time. On each pass it takes the next unsorted element, compares it backward against the already-sorted portion, shifts larger elements one position to the right, and drops the element into the gap. The mental model most people use is sorting a hand of playing cards: you pick up one card at a time and slide it into its correct place among the cards you already hold.

In this course, insertion sort matters for two reasons. First, it is simple enough that you can trace every comparison and shift by hand, which makes it an ideal vehicle for learning how to count operations and derive Big O bounds. Second, its performance profile is genuinely useful: it runs in linear time on nearly-sorted input, sorts in place with O(1) extra memory, and is stable, which is why real-world hybrid sorts fall back to it for small subarrays.

The videos below are taught in C++ and Java, but the algorithm is language-independent — the loop structure translates directly to JavaScript, so watch the logic and then write your own JS version. As you watch, pay attention to three things: the role of the inner while loop (shifting versus swapping), why the comparison uses a strict greater-than (this is what preserves stability), and how the number of shifts changes between already-sorted, random, and reverse-sorted input. Those observations are exactly what you need for the complexity and comparison subtopics.

Merge Sort

Introduction

Merge sort is the classic example of divide-and-conquer: split an array in half, sort each half recursively, then merge the two sorted halves back into one sorted array. The real work happens not in the splitting but in the merge step, where two already-sorted sequences are combined in linear time by repeatedly taking the smaller of the two front elements. Because the array is halved at every level of recursion and each level does O(n) merging work, merge sort runs in O(n log n) time on every input — best, average, and worst case alike.

That consistency is why merge sort matters in this course. Unlike bubble sort or insertion sort, it does not degrade on reversed or random data, and unlike quicksort it has no pathological worst case. The trade-off is memory: a straightforward implementation allocates auxiliary arrays, giving O(n) auxiliary space rather than quicksort's in-place behavior. Merge sort is also stable, which matters when you sort records by one key after another.

As you watch these videos, trace the recursion carefully: note the base case (an array of length 0 or 1 is already sorted), the point where recursion stops and merging begins, and the order in which merges actually execute. Pay particular attention to the merge helper — the two index pointers, the comparison, and the cleanup loops that copy any leftover elements. The videos below use C++ and Java, so translate the logic into JavaScript as you go; the control flow is identical, and array slicing in JavaScript often makes the code shorter than the examples shown.

Quicksort

Introduction

Quicksort is a divide-and-conquer sorting algorithm built around a single powerful idea: partitioning. You choose one element as the pivot, rearrange the array so that everything smaller sits to the pivot's left and everything larger sits to its right, and then recursively sort the two sides. Unlike merge sort, the combining step is free — once both halves are sorted in place, the whole array is sorted.

This topic matters because quicksort is the algorithm most language runtimes reach for in practice. Its average-case running time is O(n log n) with small constant factors and no large auxiliary array, but a poor pivot choice on already-sorted or adversarial input degrades it to O(n^2). Understanding why that happens — and how pivot strategies such as median-of-three or randomization push you back toward the average case — is exactly the kind of reasoning this module asks you to do.

As you watch, keep three questions in front of you. First, trace the partition loop carefully: which pointers move, when do swaps happen, and where does the pivot finally land? Second, notice how the recursion depth depends on how balanced the partitions are, since that is the source of both the best and worst cases. Third, watch the code structure — the videos below use Python and Java, so plan to translate the same recursive structure into JavaScript, where array indices, swaps, and recursive calls work much the same way.

Comparing Sorting Algorithms

Introduction

Once you can write bubble sort, insertion sort, merge sort, and quicksort, the next question is the one that actually matters in practice: which one should you use, and why? This topic puts the four algorithms side by side and compares them on the dimensions that drive real decisions — best, average, and worst-case time complexity, extra memory usage, whether equal elements keep their original relative order (stability), and how each behaves on small inputs versus large ones.

Input order matters more than students usually expect. Insertion sort is nearly linear on data that is already almost sorted, while a naive quicksort pivot choice can degrade to O(n^2) on sorted input. Memory matters too: merge sort's O(n) auxiliary space can be a problem on large datasets, and quicksort still carries recursion stack overhead even though it sorts in place. Building a mental comparison table — algorithm, best/average/worst time, space, stable or not, typical use case — is the core skill of this topic.

As you watch the videos below, keep that table open and fill it in. Note where different sources agree on the Big O values, pay attention to any assumptions being made (such as pivot strategy or whether a linked list or array is being sorted), and watch the animated comparisons to connect the abstract complexity classes to visible differences in how many operations each algorithm performs.
