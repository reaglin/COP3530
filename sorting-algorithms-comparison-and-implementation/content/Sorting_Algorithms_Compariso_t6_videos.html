Introduction

Once you can write bubble sort, insertion sort, merge sort, and quicksort, the next question is the one that actually matters in practice: which one should you use, and why? This topic puts the four algorithms side by side and compares them on the dimensions that drive real decisions — best, average, and worst-case time complexity, extra memory usage, whether equal elements keep their original relative order (stability), and how each behaves on small inputs versus large ones.

Input order matters more than students usually expect. Insertion sort is nearly linear on data that is already almost sorted, while a naive quicksort pivot choice can degrade to O(n^2) on sorted input. Memory matters too: merge sort's O(n) auxiliary space can be a problem on large datasets, and quicksort still carries recursion stack overhead even though it sorts in place. Building a mental comparison table — algorithm, best/average/worst time, space, stable or not, typical use case — is the core skill of this topic.

As you watch the videos below, keep that table open and fill it in. Note where different sources agree on the Big O values, pay attention to any assumptions being made (such as pivot strategy or whether a linked list or array is being sorted), and watch the animated comparisons to connect the abstract complexity classes to visible differences in how many operations each algorithm performs.
