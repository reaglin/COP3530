Introduction

Merge sort is the classic example of divide-and-conquer: split an array in half, sort each half recursively, then merge the two sorted halves back into one sorted array. The real work happens not in the splitting but in the merge step, where two already-sorted sequences are combined in linear time by repeatedly taking the smaller of the two front elements. Because the array is halved at every level of recursion and each level does O(n) merging work, merge sort runs in O(n log n) time on every input — best, average, and worst case alike.

That consistency is why merge sort matters in this course. Unlike bubble sort or insertion sort, it does not degrade on reversed or random data, and unlike quicksort it has no pathological worst case. The trade-off is memory: a straightforward implementation allocates auxiliary arrays, giving O(n) auxiliary space rather than quicksort's in-place behavior. Merge sort is also stable, which matters when you sort records by one key after another.

As you watch these videos, trace the recursion carefully: note the base case (an array of length 0 or 1 is already sorted), the point where recursion stops and merging begins, and the order in which merges actually execute. Pay particular attention to the merge helper — the two index pointers, the comparison, and the cleanup loops that copy any leftover elements. The videos below use C++ and Java, so translate the logic into JavaScript as you go; the control flow is identical, and array slicing in JavaScript often makes the code shorter than the examples shown.
