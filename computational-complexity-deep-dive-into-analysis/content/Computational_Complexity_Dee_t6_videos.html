Introduction

So far in this course you have learned the vocabulary of asymptotic analysis — Big O, Omega, and Theta — and the mechanics of counting operations. This topic puts that vocabulary to work on algorithms you already know how to code: linear search, binary search, bubble sort, selection sort, and merge sort. The goal is not to memorize a table of complexities but to be able to reconstruct each result from the structure of the algorithm itself.

That skill matters because the same handful of structural patterns reappear constantly. A single pass over n elements gives you O(n); a loop nested inside another loop over the same data gives you O(n^2); repeatedly halving a search space gives you O(log n); and splitting a problem in half and merging the results gives you O(n log n). Once you can recognize these patterns, you can analyze unfamiliar code without memorizing anything new.

As you watch the videos below, pay attention to three things: which operation is being counted as the dominant one, how the count changes between the best, average, and worst case, and why a particular notation is chosen to report the result. Notice especially that an algorithm can have different best- and worst-case behavior — optimized bubble sort is the classic example — and that reporting only Big O hides that distinction. Try pausing each video and deriving the bound yourself before the presenter states it.

How These Videos Support the Learning Outcomes

Together these videos move from a single algorithm to a comparative view. The binary search video gives you the recursive-halving pattern behind O(log n), and the optimized bubble sort video shows how a small implementation change separates best-case from worst-case behavior — both directly supporting the derivation of best, worst, and average cases (MO2) and the classification of loop and halving patterns into growth-rate categories (MO3).
