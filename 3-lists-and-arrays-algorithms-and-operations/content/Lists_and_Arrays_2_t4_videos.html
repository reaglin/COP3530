Introduction

Searching is one of the most common things we ask a program to do: given a collection of data, find whether a particular value is present and, if so, where. In this topic we look at two classic approaches. Linear search walks through a list one element at a time and compares each item to the target; it works on any array, sorted or not. Binary search repeatedly cuts a sorted array in half, discarding the portion that cannot contain the target, which makes it dramatically faster but adds the requirement that the data already be in order.

These algorithms matter in this course for two reasons. First, they are the simplest realistic setting for reasoning about Big O: linear search is O(n), binary search is O(log n), and you can see exactly why by counting comparisons. Second, they force you to think about trade-offs. Binary search is faster per lookup, but if the data is unsorted you must pay the cost of sorting first, so the "better" algorithm depends on the scenario.

As you watch the videos below, pay attention to three things: the preconditions each algorithm requires, the exact loop structure and index arithmetic (especially the low, high, and mid pointers in binary search, and how the boundaries are updated), and the comparison counts the presenters use to justify the running time. The videos use pseudocode and Python, so after watching, practice rewriting each algorithm in JavaScript using a while or for loop over an array, and test it on arrays where the target is first, last, in the middle, and absent entirely.
