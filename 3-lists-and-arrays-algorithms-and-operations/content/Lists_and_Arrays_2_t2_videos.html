Introduction

Inserting an element into an array sounds trivial until you look at what the machine actually has to do. Because array elements occupy contiguous positions and are reached by index, adding a value anywhere other than the very end forces every element after that point to shift one slot to the right. That shifting is the whole story of insertion: it determines the algorithm you write, the edge cases you must handle, and the cost you pay.

In this topic we work through three cases. Insertion at the end is the cheap case, usually a constant-time operation (amortized, when a dynamic array occasionally has to grow and copy). Insertion at the beginning is the expensive case, because every existing element has to move. Insertion at an arbitrary position sits in between but is analyzed the same way in Big O terms. Alongside JavaScript's built-in methods such as push, unshift, and splice, you should be able to write the manual algorithm yourself: loop backward from the last element, copy each value one position forward, then place the new value in the opened slot.

As you watch the videos below, keep two questions in mind. First, how many elements move for this insertion, and how does that number depend on the insertion position and the array length? Second, what happens to capacity when the array is full? The examples are shown in C in two of the videos and in JavaScript in the third, but the underlying shifting behavior and the resulting O(n) worst case are the same in both languages.
