Introduction

Deletion looks simple — "just remove the item" — but in an array it is rarely that simple. Because array elements live in contiguous positions, removing one from anywhere other than the end leaves a hole that must be repaired by shifting every following element back one slot. That shifting is the hidden cost behind most deletion operations, and it is the reason deleting from the end is cheap while deleting from the beginning or middle is not.

In this topic you will work through the main deletion scenarios: removing from the end, from the beginning, from an arbitrary middle index, and removing by value rather than by position. You will also contrast mutating approaches (which change the original array in place, such as pop, shift, and splice) with non-mutating approaches like filter, which leaves the original untouched and returns a new array containing only the elements you wanted to keep. Knowing which style you are using matters a great deal once arrays are shared across functions.

As you watch, keep three questions in mind. First, what physically happens to the remaining elements and to the length after a removal? Second, how many element moves does each operation require in the worst case — constant work, or work proportional to n? Third, does the method you are using modify the original array or return a new one? The videos below approach these questions from two angles: a low-level C view that makes the shifting and memory behavior visible, and a practical JavaScript walkthrough of the built-in methods you will actually write in this course.
