Introduction

Every data structure, no matter how simple or complex, is ultimately judged by what you can do with it and how much that costs. For lists and arrays, four operations form the core vocabulary: accessing an element at a given position, searching for an element by value, inserting a new element, and deleting an existing one. This topic asks you to describe each of these precisely — what steps the machine actually performs — before attaching any complexity notation to them.

The critical insight in this topic is that cost depends on position. Accessing the fifth element of an array is not the same work as accessing the fifth element of a singly linked list; inserting at the front of an array is not the same work as inserting at the end. Once you can articulate why shifting elements, traversing pointers, or indexing directly differ in effort, Big O notation becomes a natural shorthand rather than a memorized table.

The videos below extend the same operation vocabulary to other structures. As you watch, keep a running mental checklist: for each operation shown, ask where the work happens, whether the position of the operation changes the amount of work, and how the structure's layout makes some operations cheap and others expensive. That habit of questioning — not the specific structures demonstrated — is what carries into the rest of the course.

How These Videos Support the Learning Outcomes

Both videos reinforce MO2 by presenting insertion, deletion, and search as the defining operations of a data structure and showing exactly what steps each requires. The stack lecture speaks directly to the idea that position determines cost, since restricting insertion and deletion to one end keeps those operations constant-time, which supports the reasoning behind MO3. The trie video widens your view by applying the same operation vocabulary to a structure with a very different layout, which supports MO1's emphasis on how structural characteristics shape behavior and prepares you for the trade-off reasoning required by MO4. Use both as practice in asking the central question of this module: for this structure and this position, how much work does the operation actually take?
