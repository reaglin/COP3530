Introduction

An array gives you a fixed block of memory: you decide how many slots you need, and that decision is locked in when the array is created. A list, by contrast, is designed to be dynamic — it grows and shrinks as elements are added and removed, so the programmer does not have to predict the final size in advance. This topic examines how that dynamic behavior is actually achieved, either by reallocating and copying a larger backing array behind the scenes, or by linking separately allocated nodes together so that each new element simply gets its own piece of memory.

These mechanics matter for the rest of the course because they explain where the cost of an operation comes from. Resizing an array is not free: a new, larger block must be allocated and every existing element copied into it. Linked structures avoid that copying but give up the constant-time indexed access that contiguous memory provides. Understanding both mechanisms is what lets you say, with evidence, why one structure is the better fit for a given use case.

As you watch, pay attention to three things: what happens in memory at the moment a structure runs out of room, how elements are shifted or re-linked when something is inserted or removed in the middle, and how you reach the element at a particular position. Keep a running list of the trade-offs you notice — fixed versus variable size, contiguous versus scattered memory, cheap indexing versus cheap insertion. Those notes will feed directly into the Big O discussion later in this module.
