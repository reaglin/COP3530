Introduction

Big O notation becomes genuinely useful the moment you apply it to real operations on real structures. In this topic you take the four core operations you already know — access, search, insertion, and deletion — and attach a cost class to each one as it behaves on an array and on a linked list. Accessing an array element by index is O(1) because address arithmetic finds the slot directly, while searching an unsorted sequence is O(n) because, in the worst case, every element must be examined. Insertion and deletion are the interesting cases: the cost depends on position, since shifting elements in an array or walking to a node in a list changes the work required.

This matters because data structure selection is an engineering decision, not a style preference. Once you can say that an array gives O(1) indexed access but O(n) insertion at the front, and that a linked list reverses that profile, you can justify a choice for a specific use case rather than guessing. That reasoning — matching the operations your program performs most often to the structure that makes them cheap — is the skill the rest of COP3530 builds on.

As you watch, focus on the counting method: how does the presenter decide which statements execute once versus n times, and how do constants and lower-order terms get dropped? Pay attention to the vocabulary of complexity classes so you can recognize O(1), O(n), and O(n^2) patterns on sight, and keep asking yourself which array or list operation each example resembles.

How These Videos Support the Learning Outcomes

Together these videos give you the analytical tools that MO3 and MO4 require. The constant-time and linear-time videos teach the counting procedure that lets you classify an operation as O(1) or O(n), which is precisely what MO3 asks you to do for array access and sequential search; the complexity-classes survey adds O(n^2) and establishes the ranking among classes. That ranking is what makes MO4 possible — once you can order the classes, you can weigh an array's cheap indexed access against a list's cheaper front insertion and defend a choice. The videos reinforce MO2 indirectly as well, since the cost of insertion and deletion by position is only meaningful once you can count the shifting or traversal steps involved, and they support the structural comparison in MO1 by giving you a quantitative vocabulary for the differences between the two layouts.
