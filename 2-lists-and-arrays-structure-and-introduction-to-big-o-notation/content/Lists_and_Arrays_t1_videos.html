Introduction

Data structures are the organized ways we store data in memory so that a program can find it, change it, and reuse it efficiently. Arrays and lists are the two starting points for almost every other structure you will meet in this course: an array is a fixed-size block of contiguous memory whose elements are reached by index, while a linked list is a chain of nodes where each node holds a value and a reference to the next node. Both are ordered collections, but they organize memory in very different ways, and that difference drives everything else.

This topic matters because the rest of COP3530 builds on it. Stacks, queues, hash tables, trees, and graphs are all implemented on top of array-like or node-based storage, and the trade-offs you learn here — fast indexed access versus cheap insertion and deletion — reappear constantly. Getting comfortable now with how memory is laid out, what indexing really means, and when resizing is required will make the Big O analysis later in the module feel like a natural next step rather than a separate subject.

As you watch, keep a short comparison table going. For each structure, note: how elements are located (by index or by following links), whether the size is fixed or grows, what happens when you insert or delete at the front, middle, or end, and what extra memory the structure costs. Try to express each answer in plain words first; attaching Big O labels comes later in the module.
