Introduction

Every recursive function is built from two parts. The base case is the condition under which the function stops calling itself and simply returns a value; the recursive case is the branch in which the function calls itself on a smaller or simpler version of the original problem. Think of the recursive case as the engine that drives the computation forward and the base case as the brake that stops it at the right moment.

Both parts are required, and they must work together. A function with no reachable base case never stops, and each unfinished call keeps a stack frame alive until the runtime runs out of space and throws a stack overflow error. Just as dangerous is a recursive case that does not actually converge — for example, calling the function again on the same input, or shrinking the input in a way that skips past the stopping condition. In this course you will see this pattern repeatedly in factorial, Fibonacci, list and tree traversal, and divide-and-conquer algorithms, so recognizing the two components quickly is a skill worth building now.

As you watch the videos below, do three things. First, pause at each code example and point to the exact line that is the base case and the exact line that is the recursive case. Second, ask how the argument changes on each call and convince yourself it must eventually reach the base case. Third, notice how the speakers describe what happens on the call stack, since that is how an unterminated recursion turns into a crash rather than an infinite loop.
