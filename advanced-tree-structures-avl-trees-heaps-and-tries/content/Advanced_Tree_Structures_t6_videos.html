Introduction

A trie (also called a prefix tree) is a tree structure built specifically for storing strings. Instead of storing an entire key at a single node, a trie spreads a string across a path: each edge or node position corresponds to one character, and a word is represented by the sequence of characters encountered from the root down to a node marked as the end of a word. Because strings that begin the same way share the same initial path, tries naturally group words by common prefix.

This matters in COP3530 because tries trade memory for predictable speed. Lookup in a balanced BST costs O(log n) comparisons of whole strings, while a trie lookup costs roughly O(m) steps for a string of length m, independent of how many words are stored. That makes tries the structure behind autocomplete, spell-checking, IP routing tables, and dictionary word games. The cost is space: every node may hold an array or map of child pointers, one slot per possible character.

As you watch, pay close attention to four things: how a node is represented (child array versus hash map, plus the end-of-word flag), how insertion walks down the tree creating nodes only when a child is missing, how search distinguishes "this prefix exists" from "this complete word exists," and how deletion must avoid removing nodes that are still needed by other words. Try tracing a small word set such as cat, car, card, and dog by hand on paper, then check your drawing against the walkthroughs in the videos.

How These Videos Support the Learning Outcomes

Together these videos target MO4 most directly: each one builds a trie from a set of strings and traces character-by-character traversal for insertion and search, which is exactly the skill you must demonstrate. They also support MO1, since seeing that trie lookup depends on string length rather than the number of stored keys clarifies why tries sidestep the degradation that plagues unbalanced binary search trees on string data. Finally, the discussion of child arrays, node counts, and memory overhead in these walkthroughs gives you the evidence needed for MO5, where you must weigh a trie's O(m) search time against its space cost and justify choosing it over an AVL tree or heap for a given problem.
