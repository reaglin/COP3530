Introduction

A queue is an abstract data type that organizes elements in first-in, first-out (FIFO) order: items join at one end, called the rear or tail, and leave from the other end, called the front or head. What makes the queue useful is not a clever internal layout but the small, strictly defined set of operations it exposes. In this topic you study those operations one at a time — enqueue, dequeue, peek (front), and isEmpty — and learn exactly what each one does to the structure's state.

These operations matter because every later queue topic depends on them. When you implement a queue with an array or a linked list, you are really deciding how to make these four behaviors correct and efficient. Edge cases live here too: dequeueing or peeking an empty queue (underflow) and enqueueing into a full fixed-size array (overflow) are the conditions that separate working code from code that silently corrupts data.

As you watch, track two things. First, the front and rear indices or pointers: note precisely when each one moves, and what values they hold when the queue is empty versus holding one element. Second, the expected outcome of each operation — what is returned, what changes, and what error or condition is signaled when the operation cannot be performed.
