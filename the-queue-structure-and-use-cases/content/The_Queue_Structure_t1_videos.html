Introduction

A queue is one of the most intuitive data structures you will meet in this course, because you already use one every time you wait in line. Formally, a queue is an ordered collection in which elements are added at one end, called the rear or tail, and removed from the other end, called the front or head. This single restriction produces the First-In, First-Out (FIFO) ordering principle: the element that has waited the longest is the next one to leave.

In COP3530 the queue matters for two reasons. First, it is a clean example of an abstract data type (ADT): the interface — enqueue, dequeue, peek, isEmpty — is defined by behavior, not by any particular implementation, and the same interface can be built on an array or on a linked list. Second, queues appear constantly inside larger algorithms and systems, from CPU and print scheduling to breadth-first search on graphs, so understanding them now pays off later in the course.

As you watch the videos below, keep three questions in mind. What exactly happens to the front and rear pointers during an enqueue and a dequeue? Which conditions count as edge cases (empty queue, full queue, a single remaining element)? And how does the queue's access pattern differ from a stack's, where insertion and removal happen at the same end? Being able to answer those questions in your own words is the goal of this topic.
